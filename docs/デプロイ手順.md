# デプロイ手順

みらい議会＠全国地方議会を本番環境に出す手順です。構成は設計 v3 の 2.5節のとおりです。

| 用途 | サービス | 備考 |
|---|---|---|
| 公開サイト（`web/`） | Vercel | プロジェクトを2つ作る（web・admin） |
| 管理画面（`admin/`） | Vercel | |
| DB | Neon（PostgreSQL） | アプリは接続プール（`-pooler`）の URL、マイグレーションは直接接続の URL |
| ファイル（サムネイル・取り込んだ CSV） | Cloudflare R2 | 公開 URL（r2.dev かカスタムドメイン）で配信する |
| AI | Google Gemini API | AI チャット・インタビューなど（ふりがなは辞書で付けるので AI を使わない） |
| CI・CD | GitHub Actions | CI は `code_check.yml`・`integration_test.yml`。CD は `deploy.yml` |

全体の流れは次のとおりです。初回は 1〜8 を順に行い、2回目以降は「9. 2回目以降のデプロイ」だけです。

| 手順 | やり方 |
|---|---|
| 1. Neon で DB を作る | 画面 |
| 2. マイグレーションを当てる | ターミナル |
| 3. 初期データを入れる | ターミナル |
| 4. 最初の管理者を作る | ターミナル |
| 5. Cloudflare R2 でファイルの置き場所を作り、Gemini の API キーを作る | 画面 |
| 6. Vercel にプロジェクトを2つ作り、環境変数を入れてデプロイする | 画面 |
| 7. GitHub Actions の CD を有効にする | 画面（ファイルのコミットだけ git） |
| 8. 公開前の確認 | ブラウザ |

各サービスの画面の操作は「画面での操作」に、ボタンやメニューの名前を英語のまま書いています（2026年10月時点。名前や配置は変わることがあります）。

ターミナルが要るのは 2〜4 だけです。手元の PC に Node.js 20 と pnpm を入れ、このリポジトリを clone して `pnpm install` しておきます。

> コマンドはリポジトリのルートで実行します。本番の接続 URL などの秘密の値はターミナルの履歴に残さないよう、`export` で一時的に入れるか、パスワード管理ツールから貼り付けてください。

---

## 1. Neon で DB を作る

### 画面での操作

1. [Neon](https://console.neon.tech/) にサインアップします（GitHub アカウントでも可）。
2. 「New Project」を押し、次のように入れて「Create」。

   | 項目 | 値 |
   |---|---|
   | Project name | 例: `mirai-gikai-zenkoku` |
   | Postgres version | 17（CI の統合テストと同じ） |
   | Region | 日本に近いところ（一覧に東京があれば東京、なければシンガポール）。6章の Vercel の Function Region と揃える |
   | Database name | 既定の `neondb` のままでよい |

3. プロジェクトの Dashboard で「Connect」を押し、接続 URL を2つ控えます。ダイアログの「Connection pooling」をオンにすると接続プールの URL、オフにすると直接接続の URL が出ます。

   | 名前 | 使う場所 | 見分け方 |
   |---|---|---|
   | 接続プールの URL | アプリ（Vercel の `DATABASE_URL`） | ホスト名に `-pooler` が付く |
   | 直接接続の URL | マイグレーション・初期データ（手元と GitHub Actions） | `-pooler` が付かない |

   アプリは接続プール越しに使うため、DB の接続で prepared statement を使わない設定にしてあります（`packages/db/src/client.ts`）。マイグレーションはプールを通すと失敗することがあるので、直接接続を使います。

4. 左のメニューの「SQL Editor」で、あとから中身を確かめられます（例: 2章のあとに `select count(*) from bills;`）。「Tables」でもテーブルを見られます。
5. プレビュー用・ステージング用の DB が要るときは、左のメニューの「Branches」→「New Branch」で本番から分けて作ります（今はプレビューのデプロイを止めているので不要。7章）。

## 2. マイグレーションを当てる

```bash
export DATABASE_URL='<Neon の直接接続 URL>'
```

```bash
pnpm --filter @mirai-gikai/db migrate
```

- `packages/db/migrations/` の SQL を順に当てます。当てたものは DB の `drizzle.__drizzle_migrations` に記録され、2回目以降は新しいものだけを当てます。
- パスワードのハッシュに使う `pgcrypto` 拡張は、マイグレーション（`0001_functions.sql`）が作ります。
- ルートの `pnpm db:migrate` は `.env` を読むので、本番には使わないでください（`.env` はローカルの DB を指しています）。
- Neon の SQL Editor に SQL を貼って当てるのはやめてください。`drizzle.__drizzle_migrations` に記録が残らず、次のマイグレーションで同じ SQL をもう一度当てようとして失敗します。
- 7章の CD を入れたあとは、ブラウザだけで当てられます（GitHub の「Actions」→「Migrate DB then Deploy」→「Run workflow」）。初回も、先に 7章を済ませればこの方法で当てられます（そのときは続けてデプロイも走ります）。

## 3. 初期データを入れる

```bash
pnpm --filter @mirai-gikai/seed seed:initial
```

（`DATABASE_URL` は 2章で入れた直接接続の URL のまま）

入るもの（設計 v3 8章）:

| データ | 件数 |
|---|---|
| タグ | 13 |
| 47都道府県議会の議会マスタ | 47 |
| 愛知県議会の会期・議案・議決結果 | 会期5・議案226（うち解説付き5）。すべて公開 |
| 46都道府県議会のダミー | 議案138（会期・会派つき）。件名に「【ダミー】」 |

- データを消すことはなく、ローカル用の管理者も作りません。
- 愛知県議会の議案が既にあると止まります（管理画面で直した公開状態や解説を上書きしないため）。どうしても入れ直すときだけ `--force` を付けます。
- ローカル開発用の `pnpm seed` は DB を空にしてから入れるので、ローカル以外の DB では動かないようにしてあります。

あとからダミーだけを入れ直すときは `pnpm --filter @mirai-gikai/seed seed:dummy`（実データのある議会には入れません）。

## 4. 最初の管理者を作る

```bash
pnpm --filter @mirai-gikai/seed admin:create <メールアドレス>
```

- 初期パスワードが1度だけ表示されます。本人に安全な方法で渡し、初回ログインで変えてもらいます。
- 2人目以降の管理者は管理画面の「アカウント」から作ります。管理者は全員同じ権限で、すべての議会・機能を扱えます。
- パスワードを忘れたときは `admin:create <メールアドレス> --reset` で初期パスワードを発行し直します（ログイン中のセッションも消えます）。

終わったら `unset DATABASE_URL` で手元の環境変数を消しておきます。

## 5. ファイルの置き場所（Cloudflare R2）と AI のキー（Gemini）を用意する

### 5.1 Cloudflare R2（画面での操作）

管理画面で上げたサムネイル画像と、取り込んだ CSV の元ファイルを置きます。

1. [Cloudflare のダッシュボード](https://dash.cloudflare.com/) にログインし、左のメニューの「R2 Object Storage」を開きます（初回は支払い方法の登録を求められます。無料枠の範囲なら請求は発生しません）。
2. 「Create bucket」を押し、次のように入れて「Create bucket」。

   | 項目 | 値 |
   |---|---|
   | Bucket name | 例: `mirai-gikai-zenkoku`（これが `R2_BUCKET`） |
   | Location | 「Automatic」で、Location hint を「Asia-Pacific」 |
   | Default Storage Class | Standard |

3. 作ったバケットの「Settings」タブで、公開アクセスを有効にします。
   - 独自ドメインを使うなら「Custom Domains」の「Add」で `files.example.jp` などを登録（そのドメインを Cloudflare で管理している必要があります）
   - 使わないなら「Public Development URL」（R2.dev subdomain）の「Enable」を押し、確認欄に `allow` と入れる（アクセス数の制限があるので、本番は独自ドメインがおすすめ）
   - ここで出た URL（`https://pub-xxxx.r2.dev` か `https://files.example.jp`）が `R2_PUBLIC_URL` です
4. R2 の Overview に戻り、右側の「Account Details」の「Account ID」を控えます（これが `R2_ACCOUNT_ID`）。
5. 同じ欄の「API Tokens」の「Manage」→「Create Account API token」（または「Create User API token」）を押し、次のように入れて「Create API Token」。

   | 項目 | 値 |
   |---|---|
   | Token name | 例: `mirai-gikai-admin` |
   | Permissions | Object Read & Write |
   | Specify bucket(s) | Apply to specific buckets only → 2. のバケット |
   | TTL | Forever |

6. 表示される「Access Key ID」と「Secret Access Key」を控えます（`R2_ACCESS_KEY_ID`・`R2_SECRET_ACCESS_KEY`）。Secret はこの画面でしか見られません。

取り込んだ CSV の元ファイルも公開 URL 配下に置かれますが、ファイル名がランダムな ID なので推測はできません。CSV には公開している議案の情報しか入らない想定です。

### 5.2 Gemini の API キー（画面での操作）

1. [Google AI Studio](https://aistudio.google.com/) に、運営用の Google アカウントでログインします。
2. 左下の「Get API key」→「Create API key」で、キーを作るプロジェクト（Google Cloud のプロジェクト）を選んで作ります。これが `GOOGLE_GENERATIVE_AI_API_KEY` です。
3. 無料枠のままだと回数の制限が厳しいので、同じ画面でプロジェクトに課金（Billing）を設定します。
4. [Google Cloud コンソール](https://console.cloud.google.com/) の「お支払い」→「予算とアラート」で、月の予算とアラートのメールを設定しておきます（10章）。

## 6. Vercel にプロジェクトを2つ作る

同じ GitHub リポジトリから、web と admin の2つのプロジェクトを作ります。設定の値は 6.1 の表、環境変数は 6.2 の表を見ながら入れます。

### 6.1 プロジェクトを作る（画面での操作）

1. [Vercel](https://vercel.com/) に GitHub アカウントでログインし、右上の「Add New…」→「Project」。
2. 「Import Git Repository」で GitHub のリポジトリを選んで「Import」（一覧に出ないときは「Adjust GitHub App Permissions」で Vercel にリポジトリへのアクセスを許可します）。
3. 「Configure Project」の画面で次のように入れます。

   | 項目 | web | admin |
   |---|---|---|
   | Project Name | 例: `mirai-gikai-zenkoku-web` | 例: `mirai-gikai-zenkoku-admin` |
   | Framework Preset | Next.js | Next.js |
   | Root Directory（「Edit」で選ぶ） | `web` | `admin` |
   | Build and Output Settings | 既定のまま（pnpm と `next build` を自動で使う） | 同左 |
   | Environment Variables | 6.2 の表の値（`.env` の形の文字列を貼り付けると一度に入る） | 同左 |

4. 「Deploy」を押します。1回目のビルドはここで走ります（失敗したら環境変数を見直し、6.3 の手順で出し直します）。
5. もう一度「Add New…」→「Project」から、同じリポジトリで admin のプロジェクトを作ります。

プロジェクトを作ったら、それぞれの「Settings」で次を確かめます。

| 画面 | 項目 | 値 |
|---|---|---|
| Settings → Build and Deployment | Node.js Version | 20.x |
| Settings → Build and Deployment | Root Directory の「Include files outside of the root directory in the Build Step」 | 有効（`packages/` を使うため） |
| Settings → Functions | Function Region | Neon のリージョンに近いところ（例: Tokyo `hnd1`、Singapore `sin1`） |
| Settings → Domains | 「Add Domain」 | web に公開用（例: `gikai.example.jp`）、admin に管理用（例: `admin.gikai.example.jp`）。表示される DNS レコードをドメインの管理画面に登録する |

- `web/vercel.json`・`admin/vercel.json` で、main の Git 連携デプロイと、main 以外のプレビューを止めています（今はコミットしていない下書き。7章）。これらを入れたあとの main へのデプロイは GitHub Actions がマイグレーションのあとに行います。CD を使わず手動で出すあいだは、6.3 の「Redeploy」で出します。

### 6.2 環境変数

「Settings → Environment Variables」で、Environments を「Production」にして入れます。「Add Another」で行を足すか、`.env` の形の文字列を貼り付けると一度に入ります。秘密の値（キー・パスワード・URL に含まれる DB のパスワード）は「Sensitive」をオンにすると、あとから画面で見えなくなります。

**両方に入れるもの**

| 名前 | 値 |
|---|---|
| `DATABASE_URL` | Neon の**接続プール**の URL（`-pooler` 付き） |
| `REVALIDATE_SECRET` | ランダムな文字列（web と admin で同じ値。admin から web のキャッシュを消すときに使う） |
| `GOOGLE_GENERATIVE_AI_API_KEY` | 5.2 の Gemini API のキー |
| `NEXT_PUBLIC_WEB_URL` | 公開サイトの URL（例: `https://gikai.example.jp`） |
| `ADMIN_URL` | 管理画面の URL（例: `https://admin.gikai.example.jp`） |
| `R2_PUBLIC_URL` | 5.1 の公開 URL（web は画像の表示許可に、admin は URL の組み立てに使う） |

**web だけ**

| 名前 | 値 | |
|---|---|---|
| `VISITOR_COOKIE_SECRET` | 32文字以上のランダムな文字列 | 必須（住民の匿名 ID の署名に使う。無いとすべてのページがエラーになる） |
| `CHAT_DAILY_USER_COST_LIMIT_USD` | 例: `0.5` | 任意（AI チャットの1人1日の上限。既定 0.5） |
| `CHAT_DAILY_TOTAL_COST_LIMIT_USD` | 例: `50` | 任意（全体の1日の上限。既定 50） |
| `CHAT_MONTHLY_TOTAL_COST_LIMIT_USD` | 例: `1000` | 任意（全体の1か月の上限。既定 1000） |
| `BASIC_AUTH_USER`・`BASIC_AUTH_PASSWORD` | | 任意。公開前に関係者だけで見るときに入れ、公開するときに消す |
| `NEXT_PUBLIC_GA_TRACKING_ID` | | 任意（Google アナリティクス） |
| `LANGFUSE_PUBLIC_KEY`・`LANGFUSE_SECRET_KEY`・`LANGFUSE_BASE_URL`・`LANGFUSE_PROMPT_LABEL` | | 任意（プロンプト管理・AI の監視） |

**admin だけ**

| 名前 | 値 | |
|---|---|---|
| `R2_ACCOUNT_ID`・`R2_ACCESS_KEY_ID`・`R2_SECRET_ACCESS_KEY`・`R2_BUCKET` | 5.1 で控えた値 | 必須（無いとサムネイルや CSV の取り込みでエラー） |
| `LANGFUSE_*` | | 任意 |
| `GCP_PROJECT_ID`・`GCP_REGION`・`GCP_TOPIC_ANALYSIS_JOB`・`GCP_SA_KEY` | | 今は不要。インタビューのトピック分析を動かすとき（フェーズ3）に使う。`worker/` を GitHub Actions の定期実行に移す予定なので、そのときに見直す |

ランダムな文字列は次で作れます（ターミナルを使わないなら、パスワード管理ツールの生成機能で 48 文字以上の英数字を作っても構いません）。

```bash
openssl rand -base64 48
```

環境変数を変えても、動いているデプロイには反映されません。変えたら 6.3 の手順で出し直します（`NEXT_PUBLIC_` で始まる値はビルド時に埋め込まれるので、特に忘れないようにします）。

### 6.3 デプロイし直す（画面での操作）

1. プロジェクトの「Deployments」を開き、いちばん上（Production）の行の右の「⋯」→「Redeploy」。
2. ダイアログの「Use existing Build Cache」はオフにして「Redeploy」（環境変数を変えたあとは必ずオフ）。
3. 「Ready」になったら、「Visit」で開けることを確かめます。
4. ドメインを付けたら、`NEXT_PUBLIC_WEB_URL`・`ADMIN_URL` がそのドメインになっているか確かめ、違えば直して出し直します。

## 7. GitHub Actions の CD を有効にする

main に入ったら、Neon にマイグレーションを当ててから Vercel の web・admin をデプロイする仕組みです（新しいコードが古いスキーマの DB で動くことを防ぐ）。

使うファイル（今はコミットしていない下書き）:

| ファイル | 役割 |
|---|---|
| `.github/workflows/deploy.yml` | main への push で、マイグレーション → Deploy Hook |
| `web/vercel.json`・`admin/vercel.json` | main の Git 連携デプロイを止め、ignoreCommand を指定 |
| `scripts/vercel-ignore-build.mjs` | main 以外（プレビュー）のビルドを飛ばす |

### 画面での操作

1. **Vercel の Deploy Hook を作る:** 両方のプロジェクトで「Settings → Git」の「Deploy Hooks」に、名前（例: `github-actions`）とブランチ `main` を入れて「Create Hook」。出てきた URL を控えます（この URL を知っていれば誰でもデプロイを起こせるので、秘密として扱います）。
2. **GitHub に環境と Secrets を作る:** リポジトリの「Settings」→ 左の「Environments」→「New environment」で `production` を作ります。
   - 「Environment secrets」の「Add environment secret」で、次の3つを入れます。

     | Secret | 値 |
     |---|---|
     | `NEON_DATABASE_URL_UNPOOLED` | Neon の**直接接続**の URL |
     | `WEB_VERCEL_DEPLOY_HOOK_URL` | web の Deploy Hook の URL |
     | `ADMIN_VERCEL_DEPLOY_HOOK_URL` | admin の Deploy Hook の URL |

   - デプロイ前に人が確認したいときは、同じ画面の「Required reviewers」にチェックを入れて承認者を選び、「Save protection rules」。
   - 「Deployment branches and tags」を「Selected branches and tags」にして `main` だけを足すと、main 以外から本番に出せなくなります。
3. **ファイルを入れる:** 上の4つのファイルを見直してコミットし、main に入れます（ここだけ git の操作）。以降は main に入るたびに自動でデプロイされます。
4. **動いたか確かめる:** リポジトリの「Actions」タブで「Migrate DB then Deploy」の実行が緑になっているか見ます。承認者を付けたときは、実行の画面の「Review deployments」から承認します。
5. **手動で出し直す:** 「Actions」→ 左の「Migrate DB then Deploy」→ 右の「Run workflow」→ ブランチ `main` で「Run workflow」。

プレビューのデプロイ（PR ごと）は止めています。PR ごとの DB（Neon のブランチ）を用意すれば、`scripts/vercel-ignore-build.mjs` を直して有効にできます。

## 8. 公開前の確認

| 確認すること | 見るところ |
|---|---|
| トップに日本地図が出て、愛知県が「議案あり」の色、ほかがダミーの色 | `/` |
| 愛知県議会のトップ・議案一覧・解説付きの議案（5件）・件名のみの議案が開ける | `/aichi-pref` など |
| ダミーの議会に「表示確認用のダミーです」の帯が出る | `/tokyo-pref` など |
| ダミーの議会は `noindex`、愛知県は `index` | ページのソースの `<meta name="robots">` |
| サイトマップに愛知県の議案があり、ダミーが無い | `/sitemap.xml` |
| robots.txt にサイトマップの URL が出る | `/robots.txt` |
| AI チャットが答える（Gemini のキーが効いている） | 愛知県議会の議案ページのチャット |
| 管理画面にログインし、初回のパスワード変更ができる | admin のドメイン |
| 管理画面でサムネイルを上げて、公開サイトに表示される（R2 が効いている） | 議案編集 → 公開サイト |
| 管理画面で議案を保存すると、公開サイトにすぐ反映される（`REVALIDATE_SECRET` が合っている） | 議案編集 → 公開サイト |
| 「市」「区町村」のリンクで「現在作成中」のページが出る | ヘッダー |

関係者だけで確かめるあいだは web に `BASIC_AUTH_USER`・`BASIC_AUTH_PASSWORD` を入れておき、公開するときに消して再デプロイします。

## 9. 2回目以降のデプロイ

- **CD を有効にしたあと:** main に入れるだけです。マイグレーション → デプロイの順に自動で行います。
- **CD を有効にする前:** 次の順に手で行います。
  1. スキーマを変えたときは、先に 2章のコマンドでマイグレーションを当てる
  2. Vercel で web・admin を再デプロイする（6.3）

マイグレーションは追加だけで書き、列を消すときは「コードから使うのをやめてデプロイ」→「次のリリースで列を消すマイグレーション」の2回に分けます（デプロイ中に古いコードが動いても壊れないように）。

## 10. 運用メモ

- **戻すとき:** Vercel の「Deployments」で戻したいデプロイの行の「⋯」→「Promote to Production」（または「Instant Rollback」）。DB は戻らないので、マイグレーションを含むリリースを戻すときは、そのマイグレーションが古いコードでも動くか確かめてからにします。Neon は「Backup & Restore」（左のメニュー）で時点を指定した復元ができます。
- **ログを見る:** Vercel のプロジェクトの「Logs」で、サーバー側のエラー（`console.error`）を見られます。DB の使用量は Neon の「Monitoring」、ファイルの容量は Cloudflare の R2 のバケットの「Metrics」。
- **ダミーを消す:** 議会に実データを入れると、ダミーは確認のうえで消えます。手で消すときは管理画面の議会設定の「ダミーデータを削除」。
- **AI の費用:** AI チャットは web の `CHAT_*_COST_LIMIT_USD` で上限を決めています。Gemini 側でも Google Cloud の予算アラートを設定しておきます（5.2）。
- **Neon の容量:** 無料枠を超えそうになったら古い記録を消す方針です（設計 v3 10.2節）。消す仕組みはまだ作っていません。
